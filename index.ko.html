유지보수 도구 · 01

Jetson 펌웨어 유지보수 스크립트

NVIDIA 플래시 도구를 Bash로 호출해 환경 점검, 리소스 준비, QSPI 또는 NVMe 플래시를 수행합니다. 대상은 Jetson Orin 시리즈이며, 지원 범위는 선택한 BSP, 보드 구성, 벤더 문서에 따라 달라집니다.

받기와 실행

다운로드 후 스크립트를 검토하고 옵션을 확인하거나 대화형 메뉴를 엽니다. 플래시 전에 확인된 L4T 버전을 명시적으로 선택하십시오.

BASH / jetson-jp62.sh
curl -fL --proto '=https' -o jetson-jp62.sh \
  https://tool.kervein.club/jetson/jetson-jp62.sh
bash jetson-jp62.sh --help   # 스크립트 검토 후 실행
bash jetson-jp62.sh

플래시 전 확인
QSPI 모드는 부팅 펌웨어를 기록하므로 설정이 잘못되면 부팅이 되지 않을 수 있습니다. NVMe 모드는 대상 저장 장치를 다시 쓰고 데이터를 지웁니다. 데이터를 백업하고 캐리어 호환성, 안정적인 전원, 복구 절차를 확인하십시오. 필요한 디스크 공간은 실행 시 사전 점검으로 판정됩니다.

스크립트 모드

detect
실행 환경과 장치 상태를 점검합니다. 플래시는 하지 않습니다.
prep
BSP를 내려받아 준비합니다. sample rootfs 준비는 선택 사항입니다.
qspi
QSPI 부팅 펌웨어를 기록합니다. 시스템 디스크 재작성이 목적이 아닙니다.
nvme
대상 저장 장치를 다시 쓰고 데이터를 삭제합니다. 공식 initrd flash를 사용합니다.
target
Jetson에서 apt로 패키지를 업데이트합니다. QSPI 업그레이드와 같지 않습니다.

사용법: bash jetson-jp62.sh --mode <모드> · 버전, 진단, UART, 오프라인 옵션은 --help 또는 설명서를 참고하십시오.

플래시 전 준비물

  1. Jetson 보드Orin Nano / Orin NX(t234). 모듈과 캐리어는 EEPROM 판독값(Board ID / SKU)으로 확인합니다.
  2. 전원 어댑터19V 배럴 잭 전원. 플래시와 recovery 중에는 USB-C 전원에만 의존하지 마십시오.
  3. USB-C 데이터 케이블보드를 recovery(APX) 모드로 호스트에 연결합니다. 데이터 전송을 지원해야 하며, 충전 전용 케이블은 인식되지 않습니다.
  4. 점퍼 캡FC REC와 GND를 단락해 recovery로 진입합니다. 위치는 캐리어 실크를 확인하십시오. DevKit은 12핀 헤더의 FC REC / GND(9·10번 핀)입니다.

recovery(플래시 모드) 진입

플래시 전에 보드는 Force Recovery 모드여야 합니다. 아래 세 가지 방법은 모두 NVIDIA 공식 문서에 따른 것이며, 보드 상태에 맞는 방법을 선택하십시오.

A 전원을 끈 상태에서 (권장)

  1. 전원을 분리하고 보드가 완전히 꺼졌는지 확인합니다.
  2. Button Header의 9번과 10번 핀(FC REC → GND)에 점퍼를 장착합니다.
  3. 전원을 다시 연결하면 시스템 대신 recovery로 진입합니다.
  4. 호스트가 장치를 인식하면 점퍼를 제거합니다. 장착한 채 두면 다음 전원 인가 시 다시 recovery로 진입합니다.

B 이미 전원이 켜진 상태에서

  1. 먼저 Button Header의 9번과 10번 핀을 단락합니다.
  2. 이어서 7번과 8번 핀을 잠시 단락해 리셋합니다.
  3. 호스트가 장치를 인식하면 두 점퍼를 모두 제거합니다.

C 보드 안에서 명령으로

이미 로그인할 수 있다면 바로 recovery로 전환하십시오: sudo reboot --force forced-recovery

호스트가 장치를 인식하면 점퍼를 제거하십시오.
제거하지 않으면 다음 전원 인가 시에도 recovery로 진입합니다.
순서: 전원 차단 → 점퍼 장착(9/10) → 전원 인가 → lsusb에 0955:7523 또는 0955:7623 표시되면 제거.

확인: 호스트의 lsusb에 0955:<nnnn> NVIDIA Corp.가 표시됩니다. 7523 = Orin Nano 8GB, 7623 = Orin Nano 4GB(공식 모델 표). 표시되지 않으면 전원을 다시 인가해 재시도하십시오.

recovery 모드나 플래시 작업 없이 독립적으로 UART 로그를 수집합니다.

1 준비물

  • USB-TTL 시리얼 모듈(CP2102 / CH340 / FT232 계열, 3.3V 레벨)
  • 점퍼 와이어 3개(암-암)

2 배선(40핀 헤더)

  • Pin 8 UART_TX → 어댑터 RXD
  • Pin 10 UART_RX → 어댑터 TXD
  • GND 공통(핀 6 / 9 / 14 / 25 / 30 / 34 / 39 중 하나)

115200 8N1, 흐름 제어 없음. TX와 RX는 반드시 교차해야 하며, TX-TX로 연결하면 한 글자도 받지 못합니다.

3 캡처

  1. 스크립트 내장: bash jetson-jp62.sh --mode uart(/dev/ttyUSB* 자동 탐색, 기본 30초)
  2. 수동: screen /dev/ttyUSB0 115200(종료는 Ctrl-A 후 K), 또는 minicom -D /dev/ttyUSB0 -b 115200
  3. 캡처를 시작한 뒤 전원을 켜십시오. 해당 UART로 출력되는 로그만 수집하며 40핀 UART의 초기 부팅 로그는 보장되지 않습니다.

호스트: COMx / /dev/ttyUSBx. 보드의 ttyTHS 및 디버그 콘솔은 캐리어와 BSP에 따라 다릅니다. 출력이 없다고 펌웨어 고장으로 판단하지 말고 포트, 배선, 설정을 확인하십시오.

4 어디서 멈추는가

  • 호스트: COMx / /dev/ttyUSBx. 보드의 ttyTHS 및 디버그 콘솔은 캐리어와 BSP에 따라 다릅니다. 출력이 없다고 펌웨어 고장으로 판단하지 말고 포트, 배선, 설정을 확인하십시오.
  • UEFI에서 정지 → 부트로더 또는 디바이스 트리 설정
  • 커널에서 멈춤 → 드라이버, 루트 파일 시스템, 저장 장치
  • getty까지 도달 후 재부팅 → 애플리케이션 또는 systemd 유닛
