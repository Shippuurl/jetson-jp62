メンテナンスツール · 01

Jetson ファームウェア メンテナンススクリプト

NVIDIA の書き込みツールを Bash から呼び出し、環境チェック・リソース準備・QSPI または NVMe 書き込みを行います。対象は Jetson Orin シリーズ。対応範囲は選択した BSP、ボード構成、ベンダーのドキュメントに依存します。

スクリプトをダウンロード ↓詳細手順 ↗GitHub ソース ↗

入手と実行

ダウンロード後にスクリプトを確認し、オプションを確認するか対話メニューを開いてください。書き込み前に、確認済みの L4T バージョンを明示的に選択します。

BASH / jetson-jp62.sh
curl -fL --proto '=https' -o jetson-jp62.sh \
  https://tool.kervein.club/jetson/jetson-jp62.sh
bash jetson-jp62.sh --help   # スクリプトを確認してから実行
bash jetson-jp62.sh

書き込み前の確認
QSPI モードは起動ファームウェアを書き込むため、設定を誤ると起動できなくなる可能性があります。NVMe モードは対象ストレージを書き換え、データを消去します。データをバックアップし、キャリアの適合性、安定した電源、復旧手順を確認してください。必要なディスク容量は実行時の事前チェックで判定されます。

スクリプトのモード

detect
実行環境とデバイス状態を確認します。書き込みは行いません。
prep
BSP をダウンロードして準備します。sample rootfs の準備も可能です。
qspi
QSPI 起動ファームウェアを書き込みます。システムディスクの書き換えは目的ではありません。
nvme
対象ストレージを書き換え、データを消去します。 公式 initrd flash を呼び出します。
target
Jetson 上で apt によりパッケージを更新します。QSPI の更新とは異なります。

使い方: bash jetson-jp62.sh --mode <モード> · バージョン、診断、UART、オフラインの各オプションは --help または手順書を参照してください。

書き込み前に用意するもの

  1. Jetson ボードOrin Nano / Orin NX（t234）。モジュールとキャリアは EEPROM の読み取り値（Board ID / SKU）で確認します。
  2. 電源アダプター19V のバレルジャック給電。書き込み中や recovery 中は USB-C 給電だけに頼らないでください。
  3. USB-C データケーブルボードを recovery（APX）でホストに接続します。データ通信対応が必要で、充電専用ケーブルは認識されません。
  4. ジャンパキャップFC REC と GND を短絡して recovery に入ります。位置はキャリアのシルクを確認してください。DevKit では 12 ピンヘッダの FC REC / GND（9・10 番ピン）です。

recovery（書き込みモード）に入る

書き込み前にボードを Force Recovery モードにする必要があります。以下の 3 通りはいずれも NVIDIA 公式ドキュメントの記載です。ボードの状態に合う方法を選んでください。

A 電源を切った状態から（推奨）

  1. 電源を外し、ボードが完全に切れていることを確認します。
  2. Button Header の 9 番と 10 番（FC REC → GND）にジャンパを装着します。
  3. 電源を入れ直すと、OS は起動せず recovery に入ります。
  4. ホストがデバイスを認識したらジャンパを外します。付けたままだと次回も recovery に入ります。

B 電源が入った状態から

  1. まず Button Header の 9 番と 10 番を短絡します。
  2. 続けて 7 番と 8 番を短時間短絡してリセットします。
  3. ホストが認識したら、両方のジャンパを外します。

C ボード上でコマンドから

すでにログインできる場合は、そのまま recovery に移行できます: sudo reboot --force forced-recovery

ホストが認識したらジャンパを外してください。
外さないと、次回の電源投入時も recovery に入ります。
手順: 電源オフ → ジャンパ装着（9/10）→ 電源オン → lsusb に 0955:7523 か 0955:7623 が出たら外す。

確認: ホストの lsusb に 0955:<nnnn> NVIDIA Corp. が出ます。7523 = Orin Nano 8GB、7623 = Orin Nano 4GB（公式の型番表）。出ない場合は電源を入れ直して再試行してください。

参考NVIDIA · Force Recovery Mode（Orin Nano DevKit User Guide）NVIDIA · Jetson Linux R36.4.3 Quick StartNVIDIA Developer Forums · How to Get Into Recovery Mode

シリアル診断（UART）

起動しない、書き込みに失敗する、起動画面で止まる——こうした症状はシリアルログで起動チェーンのどの段階かを切り分けられます。SSH や recovery より低層の出力が取れます。

1 用意するもの

  • USB-TTL シリアル変換（CP2102 / CH340 / FT232 など、3.3V レベル）
  • ジャンパ線 3 本（メス-メス）

2 配線（40 ピンヘッダ）

  • Pin 8 UART_TX → アダプタの RXD
  • Pin 10 UART_RX → アダプタの TXD
  • GND を共通化（Pin 6 / 9 / 14 / 25 / 30 / 34 / 39 のいずれか）

115200 8N1、フロー制御なし。TX と RX は必ず交差させます。TX-TX で繋ぐと 1 文字も受信できません。

3 取得

  1. スクリプト内蔵: bash jetson-jp62.sh --mode uart（/dev/ttyUSB* を自動検出、既定 30 秒）
  2. 手動: screen /dev/ttyUSB0 115200（終了は Ctrl-A の後 K）、または minicom -D /dev/ttyUSB0 -b 115200
  3. 先に取得を開始し、その後にボードの電源を入れ直すと、BootROM からカーネルまでの全ログが残ります

ボード側のデバイス名は /dev/ttyTHS1（番号はリリースごとに動的に割り当てられ、ttyTHS0 固定ではありません）。権限不足なら dialout グループに追加してください。

4 どこで止まっているか

  • BootROM / MB1 / MB2 が出ない → 電源、モジュールの装着、QSPI ファームウェア
  • UEFI で停止 → bootloader またはデバイスツリー設定
  • カーネルで停止 → ドライバ、ルートファイルシステム、ストレージ
  • getty まで到達して再起動 → アプリまたは systemd ユニット
